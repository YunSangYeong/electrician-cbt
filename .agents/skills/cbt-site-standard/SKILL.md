# 자격증 CBT 사이트 표준

**표준 버전: 1.0.0.** 기준일은 2026-10-19이다. 기준 구현은 `YunSangYeong/electrician-cbt`의 정확한 커밋 `b9a682ccff1b460334b78d5bfad9375b7ec4fbb6`이다. 이 커밋에는 **학습 기준 선택 메뉴 제거**와 **실전·랜덤 두 모드의 Space 이동**이 포함된다. 사용자가 다른 판을 지정하지 않으면 이 판의 UX와 검증 절차를 기준으로 삼는다.

이 스킬은 CBT 전용 구현 표준이다. 사용자·상위 지침과 대상 저장소의 기존 지침을 우선하며 기존 작업을 보존한다. 스킬 파일을 읽는 것과 계정에 설치된 스킬로 등록하는 것은 구별한다. 코드·문항·시험 규칙의 정확성이 스킬만으로 보장된다고 말하지 않는다.

## 1. 시작과 표준 코드 확보

1. 대상 저장소의 AGENTS.md, README, Git 상태, 파일 구조, 런타임·lockfile·배포 설정을 확인한다. 현재 체크아웃을 사용하며 별도 Git worktree는 사용자가 요청하지 않으면 만들지 않는다.
2. 대상 자격증명, 저장소, 필수 기능과 배포 대상은 사용자 메시지에서 가져온다. 이미 결정된 것을 다시 묻지 않는다. 대상 자격증처럼 추론할 수 없는 필수 정보만 질문하고 독립 작업은 계속한다.
3. [기준 구현 명세](references/reference-baseline.md)를 읽는다. 기준 소스가 현재 환경에 있으면 그 정확한 커밋을 읽고, 없으면 허용된 Git 접근으로 읽기용 복사본을 확보한다. 소스 확보에 실패하면 확인한 범위와 차이를 알리며 재현 여부를 과장하지 않는다.
4. 새 저장소에서는 기준의 `src/App.tsx`, `src/styles.css`, `src/model.ts`, Vite·TypeScript 설정, package/lockfile, 테스트와 배포 workflow를 출발점으로 실제 코드를 재사용·수정한다. 제목만 보고 비슷한 앱을 새로 만들어 동일 표준이라고 주장하지 않는다.
5. 기존 앱이 있는 저장소에서는 먼저 비교하고 필요한 변경만 통합한다. `.git`, 비밀 파일, node_modules, dist, 테스트 산출물, 개인 학습 기록은 복사하지 않는다. 기존 AGENTS.md를 통째로 덮어쓰지 않는다. 적용되는 코드 라이선스를 보존한다.
6. 이 스킬 폴더 전체를 대상 저장소의 `.agents/skills/cbt-site-standard/`에 두고, [AGENTS 연결 양식](references/AGENTS.template.md)을 기존 지침과 병합한다. `$cbt-site-standard` 인식 여부를 가정하지 말고 클라우드에서는 AGENTS.md에 따른 파일 읽기로 적용한다.

## 2. 자격증 규칙과 설정 분리

[자격증 설정 양식](references/qualification-profile.template.json)을 출발점으로 대상 앱의 설정을 구성한다. 원본 코드를 수정할 때 과목·문항 수·시간·합격 기준·보기 수·저장소 이름을 여러 파일에 산재시키지 말고 설정 중심으로 분리한다.

- 자격증명, 과목/영역, 과목별 출제 수 또는 공식 선정 방식, 전체 문항 수, 시험시간, 보기 수·문항 유형, 배점, 합격 조건, 과락 유무와 규칙을 공식 자료로 확인한다.
- **전기기능사의 3과목·60문항·60분·4지선다·60점·과락 없음은 다른 자격증의 기본 사실이 아니다.** 대상 자격증 확인 없이 복사하지 않는다. 공식 규칙이 없거나 접근이 막혔으면 규칙 미확인/학습용 가정으로 표시하고 공식 시험 재현이라고 주장하지 않는다.
- 시험당 총 문항 수와 과목별 수의 합, 배점 합, 보기 수, 필요한 최소 문제은행 수가 일치하는지 확인한다. 과목별 균등 출제가 원본의 학습용 정책이었음을 구별하고 새 자격증의 공식 분포로 단정하지 않는다.
- 자격증명·과목·문항 ID 접두사·package 이름·페이지 제목·저장소 주소·Vite base·배포 주소·저장 키·생성 원고·내보내기 양식·테스트의 전기기능사 잔재를 점검하고 바꾼다.
- 저장 키는 대상 자격증별 고유 namespace를 쓴다. 같은 GitHub Pages 소유자의 여러 프로젝트는 경로가 달라도 같은 origin의 localStorage를 공유할 수 있다. `electrician-cbt:v1`을 새 프로젝트에 그대로 쓰지 않는다.
- 원본의 `2024-2026`은 기록 호환용 내부 키이지 새 자격증의 기준이 아니다. 새 앱에는 적절한 내부 자료 ID를 정한다. 날짜·버전 선택 UI를 다시 만들지 않는다. 검증된 기출 연도·회차 표시는 문항 출처 정보이므로 자료 버전 메뉴와 구별한다.
- 문제은행 목표 수는 사용자 요청에 따른다. 원본 900문항을 채우려고 무관한 전기 문제나 미검증 문항을 복사하지 않는다. 최소한 검수 완료 문항으로 모의시험 한 회가 가능해야 하며 부족하면 원인을 정확히 표시한다.

## 3. 반드시 재현할 화면과 기능

### 공통 화면

- 한국어 중심, 모바일/PC 반응형, 원본의 차분한 네이비·청록 색상, 큰 문제 글씨와 충분한 보기 간격을 기본으로 한다. 사용자가 디자인 변경을 요청하면 따른다.
- 제목은 `[대상 자격증명] 필기 CBT`로 바꾼다. 메인에는 **실전 모의시험**과 **랜덤 문제풀이** 두 모드를 크게 제공한다.
- **학습 기준 선택 메뉴, '기본 문제은행 / 준비 중' 드롭다운, 자료 버전 선택, 특정 출제기준 연도 범위를 메인에 노출하지 않는다.** 준비되지 않은 문제은행을 선택해 학습이 막히는 경로를 만들지 않는다.
- 메뉴는 학습 대시보드, 실전 모의시험, 랜덤 문제풀이, 오답노트, 북마크, 학습 통계, 문제은행 관리로 구성한다. 모바일에서는 접을 수 있는 메뉴를 제공한다.
- 대시보드에는 실제 풀이 수·정답률·최근 점수·오답 수, 최근 시험, 학습 가이드, 실제 문제 유형별 수를 보여준다. 가짜 사용 기록·합격 기록을 채우지 않는다.
- 공식 로고나 공식 서비스로 오인시키는 표시를 사용하지 않고 비공식 학습용임을 밝힌다.

### 실전 모의시험

- 검수 완료 문제 중 대상 자격증의 문항 수와 과목 규칙에 맞춰 무작위 추출한다. 같은 ID를 한 시험에 중복 출제하지 않는다. 숫자 변형 family는 가능한 한 한 번만 뽑고 부족할 때의 보충 정책을 기록한다.
- 한 번에 한 문제, 이전/다음 버튼, 전체 번호 패널, 응답/미응답/현재 표시, 변경 가능한 답안과 북마크를 제공한다.
- 남은 시간을 상단에 계속 표시한다. 시작·종료 절대 시각을 저장하고 잔여 시간을 계산한다. 새로고침·탭 비활성화·만료 후 재접속에도 종료 시각이 늘어나지 않아야 한다.
- 선택 답안을 즉시 저장한다. 시험 중 정답과 해설을 숨긴다. 종료 확인창, 만료 시 자동 제출, 제출 중복 방지, 만료 후 답안 변경 방지를 구현한다.
- 대상 규칙에 맞는 합격/불합격·점수·정답·오답·미응답·과목별 결과를 표시한다. 점수 표시 반올림과 합격 판정 원값을 혼동하지 않는다. 과락이 있는 자격증이면 실제로 반영한다.
- 제출 후 모든 보기·정답·해설·출처와 오답 필터, 그 시험의 오답만 다시 풀기를 제공한다. 미응답 처리 정책은 명확히 한다.

### 랜덤 문제풀이와 복습

- 전체/과목 선택, 순회 내 ID 중복 방지, 다음 문제 버튼을 제공한다. 답안을 선택하면 즉시 채점하고 정답·해설·출처·유형을 표시한다.
- 연속 정답과 세션 정답률, 학습 기록, 이전 학습 이어하기를 제공한다. 개별 문제 보기 변경을 즉시 채점 후 재시도로 중복 기록하지 않는다.
- 오답노트는 재학습에서 맞히면 제거한다. 북마크, 과목별 통계·취약 과목, 최근 모의시험 점수·기록을 제공한다.

### 키보드와 저장

- **실전시험은 답안 선택 후, 랜덤 학습은 채점 후 Space로 다음 문제에 이동한다.** 버튼 클릭도 계속 지원한다. 마지막 시험 문제에서 Space로 자동 제출하지 않는다.
- 답안 선택·채점·문제 이동 후 포커스를 문제 본문으로 옮겨 버튼에 남은 포커스가 Space를 가로채지 않도록 한다. 실제 keydown/keyup으로 검증한다.
- 미응답, 길게 누르기, IME, 수정키, 입력·편집·선택 컨트롤, 열린 메뉴·대화상자에서 오작동하지 않게 한다. 네이티브 버튼과 키보드 답안 선택을 보존하고 중복 이동을 방지한다.
- localStorage에 진행 중 시험, 연습 세션, 응답 기록, 오답, 북마크, 최근 시험, 로컬 등록 문항을 저장한다. 저장 실패는 경고하고 손상 원본은 자동 덮어쓰지 않는다.
- 초기화는 확인창을 거치며 기본 문제 데이터는 지우지 않는다. JSON 기록 백업을 제공한다. 원본은 백업 UI 복원 기능이 없으므로 복원을 새로 구현하지 않았다면 있다고 쓰지 않는다.
- 원본은 최근 응답 5,000개·시험 30회 보관이다. 필요하면 조정하되 화면 통계의 집계 범위와 보존 한도를 정확히 쓴다. iframe·시크릿/서드파티 저장 제한·다른 origin의 기록 분리도 고려한다.

## 4. 문제은행과 검증 표준

- 새 자격증 데이터는 전기기능사 900문항과 분리한다. 과목명만 바꿔 다른 분야 문제인 것처럼 재사용하지 않는다.
- 문항은 JSON으로 UI와 분리하고 ID, 과목, 단원, 문제, 보기, 정답 번호, 상세 해설, 난이도, 확인된 연도·회차, 유형, 자료 출처, 검증 상태, 자료 ID, 이용 조건을 기록한다. 연도·회차 미확인은 null이다.
- 원문 기출 / 복원 / 자체 제작을 구분한다. 실제 기출 원문·정답·회차·재배포 조건이 확인된 경우에만 검증된 기출로 센다. 공개된 웹페이지라고 재배포 허용으로 단정하지 않는다.
- 접근 실패 시 실제 오류와 조사한 범위를 기록한다. 민간 사이트의 문제를 무단 대량 복제하지 않는다. 기출 확보가 불가능한 동안에는 자체 제작 대안임을 사용자에게 명시한다.
- 자체 제작의 실제 근거를 정직하게 표시한다. AI의 일반 지식, 직접 확인한 공식, 검토한 외부 자료를 구분하며 읽지 않은 교재나 공식 자료를 인용하지 않는다. 저장소 URL은 작성 위치이지 외부 정답 증빙이 아니다.
- JSON/CSV 가져오기, 양식 다운로드, 검색·상태 필터·페이지 목록, 중복 제거, 검증 대기, 근거 기록 후 로컬 검수 승인, 내보내기를 제공한다. 가져오기는 로컬 등록이며 GitHub 공용 은행에 자동 게시하지 않는다.
- 최소한 ID와 정규화 본문·보기를 중복 검사한다. 보기 재배치도 고려한다. 의미상 중복 검토를 별도로 기록한다. 문항 확대 시 기존 ID와 풀이 기록 참조를 보존한다.
- 계산형은 생성 코드와 다른 검증 경로로 공식·입력·단위·답안 번호·동치 보기·반올림을 확인한다. 해설에 조건·공식·단위 변환·대입·결과를 제공하고 보기에 맞추기 위해 검증을 약화하지 않는다.
- 숫자 변형은 `family` 등으로 묶고 독립 유형 수와 조건 조합 수를 따로 보고한다. 변형 수를 기출 수나 독립 개념 수처럼 부풀리지 않는다. 결정적인 시드·ID·순서와 재생성 검증을 남긴다.
- **계산 수치 검증, 해설 문장 검토, 외부 전문가 검수, 공식 출제기준 대조는 서로 다르다.** 문장·개념을 독립 검수하지 않았다면 계산 테스트만으로 전체 해설이 검증됐다고 하지 않는다. 검증 대기는 실제 학습 은행에서 제외한다.
- 법령·규정 수치와 적용 판·시점은 공식 근거를 확인한다. 검증 없이 최신 기준에 부합한다고 표시하지 않는다.

## 5. 실제 검증과 배포

[인수 체크리스트](references/acceptance-checklist.md)를 적용한다. 검증 수는 실제 실행 결과로 보고하며 원본의 테스트 개수를 새 프로젝트의 성공 증거로 복사하지 않는다.

1. lockfile을 사용해 설치하고 필요한 타입 검사·단위 테스트·프로덕션 빌드를 실행한다. 새 자격증의 문항 수·과목 분포·합격 경계·과락·보기 수로 테스트를 바꾼다. 단순 문자열 수정에 불필요한 테스트를 양산하지 않는다.
2. PC·모바일 브라우저에서 두 모드, 답안 변경, 새로고침, 만료 자동 제출, 결과와 해설, 오답·북마크·통계·등록·초기화, 두 모드 Space와 포커스, 학습 기준 메뉴 부재를 실제 조작한다. 실기기와 에뮬레이션을 구분한다.
3. 최소 한 시험 분량 이상의 검수 문항이 있는지 확인하고 필요한 실제 기능 검증을 수행한다. 실패·미실행·차단·외부 판단 필요를 통과와 섞지 않는다.
4. Git 반영이 허용된 범위에서 변경을 검토·커밋·푸시하고 원격 커밋을 확인한다. 비밀값·개인 기록·불필요한 생성물을 올리지 않는다. 무단 force push를 하지 않는다.
5. GitHub Actions는 대상 브랜치의 검증 성공 후 GitHub Pages에 배포한다. 새 저장소의 Pages Source와 권한, `/<저장소>/` 또는 사용자 사이트 루트 경로를 확인한다. 외부 게시 권한과 환경 정책을 따른다.
6. 정확한 커밋의 CI와 배포 작업이 끝나는지 확인한다. 로컬 성공·푸시·CI·배포·공개 사이트 동작은 별개로 보고한다. 원본의 성공한 실행을 새 프로젝트의 증거로 쓰지 않는다.
7. 가능한 경우 공개 주소에서 실제 동작을 확인한다. 네트워크 차단으로 직접 열지 못하면 CI 배포 성공과 공개 페이지 검증 불가를 구분한다. 배포 확인 없이 '새로고침하면 된다'로 끝내지 않는다.
8. 기본 URL은 업데이트 후에도 유지한다. `?v=커밋`은 필요 시 캐시 갱신용이지 새로운 배포 주소가 아니다. 블로그 iframe은 기본 주소가 같으면 재작성할 필요가 없고, iframe 내부의 키보드 포커스와 저장 제한은 별도로 확인한다.

## 6. 완료와 다음 프로젝트 사용

- README에 대상 시험 규칙과 근거, 로컬 실행·빌드·테스트, 실제 문항 수와 유형/변형 수, 검수 범위, 데이터 보존 정책, Pages 설정과 배포 결과를 남긴다.
- 최종 답변에는 구현 기능, 과목·유형별 문항 수, 출처/검증 한계, 실제 테스트 결과, 커밋, CI/배포 결과·기본 주소, 남은 조치를 간결히 쓴다.
- 동일한 산출물 자체가 필요하면 고정한 커밋·lockfile·런타임·문항 데이터로 재생성한다. 스킬은 절차와 인수 기준을 정하며 다른 자격증의 정확성이나 매번 동일한 생성 결과를 보장하지 않는다.
- 새 프로젝트에 전달할 요청 예시는 [클라우드용 시작 요청](references/new-project-prompt.md)에 있다. 이 본문은 독립적으로도 사용할 수 있지만, 세부 설정·인수 기준을 위해 폴더 전체를 함께 전달하는 것을 권장한다.
